# F-065, Theme read and write

**Status**: completed
**Sprint**: S15
**Size**: L
**Depends on**: F-060, F-061

## Problem

`oxml-drawing` has no theme module or `CT_OfficeStyleSheet` export at
`crates/oxml-drawing/src/lib.rs:1`. The existing theme reader at
`crates/rdocx-oxml/src/theme.rs:9` is read-only, projects only twelve colours
and two Latin fonts, and does not model `a:fmtScheme`.

PowerPoint requires a theme part for each presentation master. Shape style
references also need typed access to the theme colour and format schemes.
F-060 and F-061 are complete and provide the fill and line types used by the
format scheme.

## Approach

Add `crates/oxml-drawing/src/theme.rs` and export it from `lib.rs`. Use this
public contract:

```rust
pub struct CT_OfficeStyleSheet {
    pub name: Option<String>,
    pub theme_elements: CT_ThemeElements,
}

pub struct CT_ThemeElements {
    pub color_scheme: CT_ColorScheme,
    pub font_scheme: CT_FontScheme,
    pub format_scheme: CT_StyleMatrix,
}

pub struct CT_ColorScheme { pub name: String, /* twelve ordered slots */ }
impl CT_ColorScheme {
    pub fn color(&self, slot: ThemeColorSlot) -> &ColorChoice;
    pub fn iter(&self) -> impl Iterator<Item = (ThemeColorSlot, &ColorChoice)>;
}

pub struct CT_FontScheme {
    pub name: String,
    pub major_font: CT_FontCollection,
    pub minor_font: CT_FontCollection,
}

pub struct CT_FontCollection {
    pub latin: ThemeTypeface,
    pub east_asian: ThemeTypeface,
    pub complex_script: ThemeTypeface,
    pub supplemental_fonts: Vec<SupplementalFont>,
}

pub struct ThemeTypeface { pub typeface: String }
pub struct SupplementalFont { pub script: String, pub typeface: String }

pub struct CT_StyleMatrix {
    pub name: String,
    pub fill_styles: Vec<Fill>,
    pub line_styles: Vec<CT_LineProperties>,
    pub effect_styles: Vec<CT_EffectStyle>,
    pub background_fill_styles: Vec<Fill>,
}

pub struct CT_EffectStyle { pub effect_list: Option<CT_EffectList> }

impl CT_OfficeStyleSheet {
    pub fn from_xml(xml: &[u8]) -> Result<Self>;
    pub fn to_xml(&self) -> Result<Vec<u8>>;
    pub fn office_default() -> Self;
}
```

The twelve colour slots reuse `ThemeColorSlot` and `ColorChoice`. The four
format-scheme lists reuse `Fill`, `CT_LineProperties`, and `CT_EffectList`.
Font collections retain Latin, East Asian, complex-script, and supplemental
script typefaces for later resolution.

Read by local name, write fixed `a:` prefixes, and emit modelled children in
schema order. Preserve unmodelled attributes and children at their original
boundaries with `OrderedRawChildren`. `office_default()` returns the complete,
schema-valid standard Office theme with three entries in each format-style
list.

## Rejected alternatives

- Extend `rdocx_oxml::theme::Theme`. The complete shared model belongs to
  `oxml-drawing`, while the released reader stays stable.
- Preserve `a:fmtScheme` as opaque XML. Later style resolution needs typed
  fill, line, effect, and background-fill lists.
- Model only Latin fonts. Later typeface resolution requires the other font
  collections and supplemental script mappings.
- Reuse the minimal OPC package test theme as `office_default()`. It is a test
  fixture, not the standard Office theme.
