## Blocking

### B1, retained public flow APIs discard the collision-resolved media map

`crates/rdocx-layout/src/engine.rs:458`
`crates/rdocx-layout/src/engine.rs:466`
`crates/rdocx-layout/src/engine.rs:926`
`crates/rdocx-layout/src/paginator.rs:83`

The retained public `layout_paragraph` API builds the collision-resolved
relationship and media maps, uses the relationship half to place alternate IDs
in its returned block, and discards the media half. `layout_table` does the same.
The public `paginate_sections` API then requires the caller to supply the media
map, but the only constructor that can reproduce the engine's deterministic
collision probing is crate-private. An external caller using the documented
retained flow and paginator APIs therefore cannot associate bytes with an
alternate ID when two distinct images share their initial `MediaId`. Building a
map with `MediaId::from_bytes` overwrites one entry, while using that map with
the returned blocks leaves the probed ID absent. The high-level `Engine::layout`
path is safe, but the same valid collision from pass 4 still produces missing or
substituted image data through the retained public path. A fix must make the
collision-resolved relationship and media maps available as one coherent public
operation, or otherwise preserve collision identity through the public flow
pipeline, with a public-path forced-collision regression.
