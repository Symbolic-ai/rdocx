## Should-fix

### S1, collision remediation rebuilds the complete media registry for every image

`crates/rdocx-layout/src/engine.rs:885`
`crates/rdocx-layout/src/engine.rs:921`
`crates/rdocx-layout/src/engine.rs:936`

Each inline or anchored image calls `media_id_for_relationship`, which calls
`media_registry` over the complete `LayoutInput`. The registry sorts every
image and clones every distinct image payload before returning one relationship
ID, then the layout entry point builds the same registry again for pagination.
A document with N distinct images used once therefore sorts the registry N plus
one times and copies total image data quadratically. Large image-heavy documents
can incur substantial avoidable allocation and latency during a render-only
cutover. Build the collision-resolved relationship and media maps once per
layout, then pass or retain that registry for paragraph, table, header, footer,
and pagination resolution.
