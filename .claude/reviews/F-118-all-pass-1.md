## Defects

### D1, public edits can move preserved children ahead of their schema slots

`crates/rpptx-chart/src/lib.rs:437`

Known opaque children are stored at the current boundary before the parser
advances to the boundary assigned to their schema name. For example, a valid
chart with `c:pivotFmts` and no `c:autoTitleDeleted` stores `c:pivotFmts` at
boundary zero. Setting the public `auto_title_deleted` field to true then
writes `c:pivotFmts` before `c:autoTitleDeleted`, which violates the
`CT_Chart` sequence. The same behavior at line 650 lets a later public
`sp_pr` or `tx_pr` insertion follow an already preserved `externalData` child.
Anchor known opaque children at their schema boundary, including when an
optional modeled predecessor was absent during parsing. Add edit-after-parse
tests for both chart and chart-space fields.

### D2, direct comments and processing instructions are discarded

`crates/rpptx-chart/src/lib.rs:322`

The chart parser ignores every event that is not a child element, its matching
end, or EOF. The chart-space parser and all three raw-shell parsers do the same
at lines 561 and 185. A comment or processing instruction directly between
ChartML children is therefore absent from the serialized part. This violates
the repository rule that unmodeled XML remains verbatim. Capture these events
at the active boundary and add direct-content preservation cases.

### D3, modeled scalar elements drop unmodeled attributes and content

`crates/rpptx-chart/src/lib.rs:723`

Scalar parsing extracts only the unqualified `val` attribute. Other
attributes are not retained, and comments inside a non-empty scalar are
explicitly accepted and discarded at line 742. Serialization rebuilds only a
canonical empty element with `val`, so producer or markup-compatibility data
on `autoTitleDeleted`, `plotVisOnly`, or `dispBlanksAs` is lost. Retain the
unmodeled scalar attributes and allowed XML events while continuing to type
and validate `val`.

### D4, foreign DrawingML children are converted into typed DrawingML

`crates/rpptx-chart/src/lib.rs:645`

The chart-space parser resolves the `c:txPr` namespace, but then delegates its
captured bytes without the inherited namespace bindings. The shared text
parser matches `bodyPr`, `lstStyle`, and `p` by local name alone at
`crates/oxml-drawing/src/text/mod.rs:111`. Consequently
`<c:txPr><x:bodyPr/><x:p/></c:txPr>` with `x` bound to a foreign namespace is
accepted and rewritten as `<c:txPr><a:bodyPr/><a:p/></c:txPr>` instead of
remaining foreign preserved XML or returning an error. The reused shape
properties path has the same namespace-blind delegation. Pass namespace
bindings into the concrete readers or validate the nested DrawingML names
before typing them. Add foreign-prefix negative and preservation cases.

### D5, the corpus gate cannot detect XML lost during the first parse

`crates/rpptx-chart/src/lib.rs:1106`

The declared gate compares the first parsed model with the model reparsed from
serialized bytes. XML that the first parse drops or wrongly converts is absent
or converted in both models, so this equality still passes. This is why the
direct comments and foreign DrawingML cases above are invisible to the current
26-part run. The approved plan requires every unmodeled corpus subtree to stay
byte-identical at its boundary. Compare the preserved regions of each original
part with the serialized part, in addition to structural model equality.

### D6, the new XML parser and writer are generated by a macro

`crates/rpptx-chart/src/lib.rs:150`

`raw_shell!` generates the parser and serializer implementations for title,
plot area, and legend. The repository's XML convention requires each
quick-xml parser and serializer to be hand-written and expressly disallows
macros and code generation for this layer. Replace the generator with concrete
implementations or a shared ordinary helper whose behavior remains visible
from the type implementation.
